# PHASE 7.4 리소스팩 복구와 실험실 시작

## 배포 및 진단

Paper 26.3과 Java 25에서 플러그인 JAR을 업데이트한다. JAR을 교체해도 기존 `config.yml`의 팩 URL과 해시는 자동으로 바뀌지 않는다. 이번 릴리스와 맞는 [배포 ZIP](../distribution/augmentwild-26.3.zip)을 사용한다. 설치기는 이 ZIP을 마지막으로 갱신한 공개 Git 커밋을 찾아 직접 HTTPS 주소와 SHA-1을 출력한다.

```bash
python3 scripts/install-pack.py
python3 scripts/install-pack.py --apply /server/plugins/AugmentWild/config.yml
```

다른 공개 HTTPS 주소를 사용한다면 `--url <ZIP 직접 주소>`를 지정한다. 설정을 바꾼 뒤 서버를 재시작한다. 재접속할 때 플러그인은 확인 가능한 이전 AugmentWild 팩 UUID만 제거하고 새 SHA-1에 대응하는 팩을 요청한다.

| 경우 | 확인 또는 조치 |
| --- | --- |
| URL 미설정 또는 SHA-1 오류 | `/aw admin art status`와 설치기 출력 확인 |
| HTTP·CRC·팩 버전 오류 | `/aw admin art validate`의 비동기 결과 확인. 서버 검증은 HTTPS에서 HTTP 200으로 직접 ZIP을 반환하는 주소를 사용한다. |
| 팩 거부·다운로드 또는 재로드 실패 | `/aw admin art report`에서 접속 세션별 응답 확인. 플레이어는 `/aw art retry`로 다시 요청한다. |
| 팩 로드 응답이 있어도 아이콘 또는 글리프가 깨짐 | `/aw art safe` 또는 화면 설정에서 기본 표시로 전환한다. 안전 모드를 끄면 새로 연 메뉴에서 팩 아이콘을 사용한다. |

`/aw art menu`와 `/aw admin art menu`에서 같은 동작을 선택할 수 있다. 서버 검사가 통과하면 다운로드 바이트, SHA-1, ZIP 무결성, 97.1 메타데이터, 릴리스 표식, 84종 아이템·모델·텍스처와 글꼴·소리 참조가 확인된다. Paper의 `SUCCESSFULLY_LOADED`는 접속 중인 클라이언트의 로드 응답으로 기록한다. 화면에서 보이는 내용은 클라이언트에서 별도로 확인한다.

## 제목과 슬롯

기존 방식은 슬롯 영역까지 내려오는 176px 폭의 이미지를 제목 글리프에 넣었다. 화면마다 행 수에 따라 36~126px 높이이며, 글꼴의 advance와 음수 간격은 텍스트 커서 위치만 옮긴다. 글리프의 그리기 영역은 인벤토리 슬롯에 맞게 잘리지 않는다. PHASE 7.4에서는 제목을 항상 기본 글꼴의 텍스트로 보내고, 인벤토리 종류와 행 수에 따른 제목 기준선과 슬롯 배치는 클라이언트에 맡긴다. 큰 패널의 폰트 등록은 배포 ZIP에서 제거했고 패널 PNG는 제작용으로 유지했다. 8px 스킬 글리프만 선택적으로 사용하며 스킬명과 상태 텍스트가 함께 표시된다.

메인 메뉴의 증강 선택과 도감은 별도 버튼이다. 도감의 나침반에서 전체·희귀도·공격·방어·이동·성장·채광·액티브·진화·시너지·공명·즐겨찾기·보유 필터를 선택한다. 우클릭 상세 화면은 발동 조건, 설정 수치, 사용 가능한 스킬 슬롯과 팩 모델의 외형을 보여 준다. 실버는 금속 팔각 프레임, 골드는 금빛 방패 프레임, 프리즘은 수정 프레임을 사용한다. 기본 아이템과 이름·희귀도 표시는 안전 모드에서도 유지된다.

## 실험실

1. 운영 월드와 분리된 기존 PvP 오버월드를 서버에서 미리 로드한다.
2. `dev.combat-lab.enabled`와 `world`를 설정하고 `/aw admin test check`를 실행해 월드·접속자·중심 청크·생성 설정을 확인한다.
3. 1인 실험은 `/aw admin test solo`로 시작한다. 플레이어는 검색이 진행되는 동안 원래 월드에 머무르고, 스냅샷을 저장한 뒤 검증된 좌표로 바로 이동한다. 월드 스폰 자체를 경유하지 않는다.
4. 미생성 청크가 원인이면 테스트 구역을 사전 생성한다. 관리자가 실험 월드에서만 생성하려는 경우 `dev.combat-lab.generate-missing-chunks: true`를 사용할 수 있다. 7.4 기본 설정은 실험 전용 크기 128과 탐색 반경 128이다. `arena-size: 0`은 운영 경기장 크기를 상속한다. 기존 서버가 큰 최종 자기장 크기를 사용한다면 그 이상 크기의 실험 경기장이 필요하다.

3×3 지표, 바다 제외, 스폰 간격, 월드 경계, 다른 플레이어가 있는 실험실의 입장 조건을 유지한다. 검색 실패 시 기존 월드에서 기다리던 플레이어는 이동하지 않는다. 운영 경기의 크기와 시간 규칙은 기존 설정을 사용한다.
