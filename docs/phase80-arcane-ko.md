## 레퍼런스와 구현 방식

- Wynncraft의 배포 방식은 서버에서 리소스팩을 제공하는 접근의 사례다. 공식 리소스팩의 내용은 복제하지 않는다. [Wynncraft 공식 포럼 FAQ](https://forums.wynncraft.com/threads/wynncraft-frequently-asked-questions.295549/)
- Model Engine의 뼈 계층은 움직임을 기능별로 나누는 참고점이다. AugmentWild는 Java 클라이언트의 아이템 모델과 Paper Display 변환을 사용한다. [Model Engine 4 모델 제작 문서](https://git.mythiccraft.io/mythiccraft/model-engine-4/-/wikis/Modeling/Creating-a-Model) · [Paper Display 엔티티](https://docs.papermc.io/paper/dev/display-entities/)
- 버튼 설명과 화면 계층은 Adventure Component를 유지한다. 게임 내 가독성은 실제 클라이언트에서 확인한다. [Paper Adventure 안내](https://docs.papermc.io/paper/dev/component-api/introduction)

고대 마법 공학의 권능을 금속 골격, 별개의 동력원, 열이나 압력의 방출로 표현한다. 시간 장치의 황동 톱니와 청록색 눈금, 공허의 자수정 경계와 검은 중심, 지진의 붉은 단층과 석재의 파편을 분리한다.

Paper와 Blender는 같은 arcane-parts.tsv 타임라인을 사용한다. HIGH는 추가 파트 1개, ULTRA는 최대 2개를 사용한다. 16블록 밖에서는 파트를 걷어내고 공개 위험 표시와 본체의 기존 가시거리 정책을 유지한다. 서버는 24개 Display 예산에서 장식을 먼저 정리한다. Display 수명은 게임 시간과 피해 판정을 변경하지 않는다.

## 테스트와 설치

Java 25로 JAR과 프로브를 빌드한다. scripts/resource-pack.py는 체크인한 JSON과 텍스처, 사운드, 파트 키와 팩 무결성을 점검한다. scripts/install-pack.py는 Git에 배포된 ZIP을 내려받아 SHA-1과 원본 바이트를 확인하고 기존 서버에서 바꿀 YAML을 출력한다.

[7.9와 동일한 촬영 방법](phase79-visual-ko.md)을 이용한다. /aw admin test preview에서 촬영 연출을 열고 HIGH와 ULTRA를 비교한다. 한 능력을 반복 재생하며 본체와 부품의 방향, 소멸, 팩 미적용 처리 순서를 확인한다. 실제 클라이언트 시험은 REAL_CLIENT_VERIFIED=NOT_RUN이다. Blockbench로 편집 파일을 여는 검증도 미실행이다. 외부 사례와 동등하다는 품질 평가는 유보한다.

[7.9 소리 비교](art80/cues-79.ogg) · [8.0 소리 비교](art80/cues-80.ogg). 동일한 순서로 그림자 이동, 검기, 파쇄, 역행, 공허, 점화, 폭발, 계약, 보호막 파괴, 진화, 시너지, 프리즘 큐를 이어 붙였다. 배포 Ogg를 사용한 오프라인 샘플이다.

새 윤곽·UI 표식·합성 음원은 프로젝트 제작물이고 기존 사용 심볼의 고지와 출처는 유지했다. 스틸 비교의 대형 형상이 잘리지 않도록 두 버전의 카메라를 같은 거리로 다시 조정했다. 좌표와 애니메이션은 배포 JSON과 트랙에서 읽었다.
