# PHASE 6.7 증강 선택과 전투 실험실

## 선택 설정

기본 5–25분 선택은 이전과 같은 XP 희귀도 공식과 1.5배·2.5배 시너지 가중치를 사용한다. 76개의 주 역할은 [AugmentRole](../src/main/java/io/github/augmentwild/augment/AugmentRole.java)에서 관리한다. 분류되지 않은 ID는 기동 로그에서 경고하고 역할 보정 없이 추첨한다.

```yaml
augments:
  draft:
    earlier-diversity: false
    final-diversity: true
    exclude-final-xp: true
```

최종 두 후보의 역할이 같으면 세 번째 후보에서 다른 역할의 유효 후보에 가중치를 더한다. 기존 시너지 가중치는 곱에 그대로 남으므로 같은 역할과 시너지 후보도 계속 추첨된다. 일반 회차의 보정을 켜면 역할이 중복되는 동안 같은 방식으로 보정한다. 후보 자격, 희귀도, 이전 후보 및 보유 후보 우선순위를 거친 뒤 역할을 적용한다. 두 옵션을 꺼도 기존 15초 선택, 자동 선택, 재추첨 횟수가 그대로다. 30분 후보는 프리즘으로만 구성한다. 유효한 후보가 부족하거나 재추첨에서 기존 후보만 남으면 순수 XP 후보를 다시 허용하고, 세 후보 자체가 존재하지 않으면 유효한 수만 표시한다.

## 결정 시드 비교

Java 25의 `bash scripts/test-domain.sh`에서 레벨 0·10·25·40·50, 목표 시너지 조각 0·1·2개 보유, 6개 회차와 재추첨 사용 유무를 비교했다. 모델마다 20,000개 합성 경기에서 최종 표시된 선택지 120,000세트를 측정했다. 후보 교환 자격과 비용·보상 확정도 모델에 넣었다. 목표 시너지 조각이 있으면 우선하고, 이외에는 후보 중 무작위로 선택했다.

| 측정 항목 | 기존 | 개선 |
|---|---:|---:|
| 최종 회차 단일 역할 후보 세트 | 989/20,000 (4.945%) | 426/20,000 (2.130%) |
| 최종 회차 순수 XP 후보 포함 | 2,325/20,000 (11.625%) | 0/20,000 |
| 강철의 왕 완성 | 590 (2.950%) | 590 (2.950%) |
| 무한 포격 완성 | 678 (3.390%) | 682 (3.410%) |
| 재앙의 기관차 완성 | 620 (3.100%) | 628 (3.140%) |
| 지옥의 군주 완성 | 938 (4.690%) | 961 (4.805%) |
| 천 개의 검 완성 | 584 (2.920%) | 583 (2.915%) |

시드가 같은 기본 1–5회차는 최초 및 적용된 재추첨 후보 ID가 모두 일치했고 회차별 희귀도 개수도 동일했다. 다섯 레벨에서 공식의 10,000개 분위 경계를 다시 확인했다. 두 모델의 마지막 60,000개 슬롯은 전부 프리즘이었다. 결과물의 `offer_*`은 전체 선택지 세트 중 해당 ID가 포함된 비율, `pick_*`은 세트에서 해당 ID를 선택한 비율이다. 역할 분류, XP 입력과 선택 정책이 PHASE 6.6 예비 모델에서 바뀌었으므로 위 표는 같은 조건으로 다시 실행한 쌍을 비교한다.

## 관리자 전투 실험실

기본값은 비활성화다. 격리된 테스트 Paper 서버에서 운영 `arena.world`와 다른 기존 오버월드를 준비한다. 바다 없는 청크를 미리 준비하고 테스트 서버 설정을 아래처럼 수정한 뒤 재시작한다. 실제 로그인한 테스트 계정을 해당 월드로 이동시키고, 모든 계정에서 `/aw join`을 실행한다. 콘솔 또는 `augmentwild.admin`과 `augmentwild.admin.test`를 모두 가진 관리자가 `/aw admin test start`를 실행한다. 일반 `admin start`로 시작하면 실험 명령을 사용할 수 없다. 진행 중 선택으로 시계가 일시정지됐을 때도 실험 명령을 보류한다.

```yaml
dev:
  combat-lab:
    enabled: true
    world: augment_lab
```

| 명령 | 동작 |
|---|---|
| `/aw admin test status` | 설정과 현재 테스트 경기 확인 |
| `/aw admin test start` | 참가자를 전용 월드의 테스트 경기로 배치 |
| `/aw admin test grant A steel_heart` | 실제 소유권·획득 경로로 부여. 같은 ID는 한 번만 부여. 교환형은 기존 비용과 GUI 사용 |
| `/aw admin test remove A steel_heart` | 해당 증강 및 원장·쿨다운·추가 효과 정리 |
| `/aw admin test list A` | 보유 ID 출력 |
| `/aw admin test clear A` | 증강과 엔진 상태 전체 정리 |
| `/aw admin test reset A` | 전체 정리 후 현재 최대 체력으로 채우고 흡수·화염·포션을 초기화 |
| `/aw admin test progress A steel_heart 20` | 보유 증강의 지원 카운터를 20으로 설정하고 상한·진화·속성을 반영 |
| `/aw admin test health A 2` | 현재 체력을 2포인트(1하트)로 설정 |
| `/aw admin test report A` | 체력·이동·크기, 조합·중첩·진화·쿨다운, 일반 흡수 및 생명의 잔향 양을 출력 |

부여와 제거는 현재 선택 회차나 재추첨을 소비하지 않는다. `progress`는 최종 원장값을 설정해 이전 소수 잔량을 비우며, 이후 전투의 중첩 지급은 실제 공명 배율을 적용한다. 영구 성장 13종, 미사일 발사 수, 검기 명중 수, 폭주 최고 속도 초, 화상 진화 누적치를 지원한다. `blood_god`는 피해 성장 원장으로 연결되며 별도의 처치 원장은 실제 처치로 진행한다. 제거된 증강이 이미 다른 엔티티에 건 바닐라 포션 효과는 해당 효과의 정상 만료를 따른다.

랩은 양쪽 명령 권한, 명시적 시작, 테스트 월드 UUID, 활성 참가를 검사한다. 참가자 외 인원이 있으면 시작하지 않으며 진행 중 비참가자가 로그인한 경우 종료한다. 경기 중 아이템 떨어뜨리기와 월드 컨테이너·엔더 상자 접근을 차단하고, 종료 시 기존 스냅샷으로 복구한다. 실험 로그는 `mode=lab`로 구분하며 운영 경기장 사용 기록에서 제외한다. 서버 운영자는 테스트 월드 접근과 외부 플러그인의 아이템 이동을 격리한다. 별도 테스트 서버에 이 설정을 사용한다.

## 실전 검증 순서

[A·B 계정의 시작과 상태 복원 기록](phase66-playtest-ko.md)을 먼저 준비한다. 같은 장비를 착용한 뒤 아래 조합을 A에게 부여한다. 각 조합의 독립 실행마다 `reset`을 하고 A·B의 `report`를 수집한다. 필요한 경우 `health`로 치명 구간을 만든다. 고유 시너지는 마지막 조각을 제거한 상태에서 같은 공격을 반복해 대조한다. 경기 ID와 보고서의 `actor-N`으로 `combat-audit` 원본·파생·흡수 기록과 매칭한다. 런타임 검증에는 실제 두 클라이언트의 공격과 GUI 조작이 포함된다.

| 조합 | 먼저 확인할 재현 |
|---|---|
| 강철의 왕 | `steel_heart stack_dinosaur heavy_fist`. 강철심장 19→20 이후 최대 체력·충격파·원본 주먹 피해 |
| 무한 포격 | `magic_missile eureka infinite_repeat`. 미사일 99→100, 중복 발사·명중·파생 묶음 |
| 재앙의 기관차 | `tank_engine calamity_giant berserk_engine`. 탱크 14→15, 폭주 진화 전후 크기·속도·접촉 |
| 지옥의 군주 | `infernal_conductor center_of_universe jeweled_gauntlet`. 화상 199→200, 자동 공격·치명타·지속 피해 |
| 천 개의 검 | `sword_wind ultimate_hydra dual_wielder`. 검기 29→30, 보조 손·가림·광역 대상 |
| 생명의 잔향 | `immortal_berserker phoenix_heart russian_doll`. 2종과 3종 각각에서 치명 피해 방지 순서·2/4하트·6초 만료·바닐라 흡수·서든데스 확인 |

마지막에 `/aw admin stop`으로 종료하고 원래 장비·XP·위치·게임 모드·속성과 종료 중 오프라인이었던 계정의 복원을 확인한다. 실제 조합 공격 및 GUI 실험은 이 작업에서 `NOT_RUN`이다.

## 성능 재현

일반 Paper smoke는 30틱 사례를 유지한다. 별도 CI 작업에서는 시드 67026, 워밍업 50틱, 측정 300틱으로 2·4·8·16개 테스트 엔티티를 같은 순서로 두 번 실행한다. 틱 p50·p95·p99, 최대, 50ms 초과 분자와 분모, 잔여 엔티티를 로그에 남긴다. 정리 후 청크 티켓을 해제한다.

```bash
./gradlew clean build paperProbeJar --stacktrace
AW_BORDER_PROBE=1 AW_EXTENDED_LOAD=1 RUNNER_TEMP="$(mktemp -d)" bash scripts/test-paper-smoke.sh
```
