# PHASE 6.6 플레이테스트 절차와 기록

## 서버와 테스트 계정

Java 25, Paper 26.3, 검증 대상 커밋의 플러그인 JAR을 사용한다. 아래 명령은 저장소에서 실행한다. Paper의 테스트 엔티티 및 보급 저장 경계 검사에는 별도의 프로브 JAR을 사용한다. 실제 플레이테스트 서버에는 `build/libs/`의 플러그인만 설치한다.

```bash
java --version
./gradlew clean build paperProbeJar --stacktrace
bash scripts/test-domain.sh
git diff --check
```

테스트 환경에는 운영 데이터와 분리된 기존 오버월드를 사용한다. PvP를 허용하고 플러그인 설정의 `arena.world`에 월드 이름을 넣는다. 기본 지형 검색은 이미 생성된 청크를 사용하므로 바다 없는 1000×1000 후보를 미리 준비한다. 운영 서버에서 `kill -9`를 실행하지 않는다. 테스트 Paper 폴더에서 환경과 로그를 기록한다.

```bash
java -Xms2G -Xmx4G -jar paper.jar --nogui
# 종료 후 결과의 유형별 보관 예
mkdir -p playtest-results/live
grep -E 'Match tempo|Match feature totals|timeline event|combat-audit|Arena search' \
  logs/latest.log > playtest-results/live/match.log
```

동일 버전의 인증된 Minecraft Java 클라이언트와 계정을 목표 인원만큼 연결한다. 계정명은 기록지에서 A–P로 바꾸고, 고정 테스트 호스트와 운영자 콘솔을 사용한다. 시험 전에 위치·게임 모드·인벤토리·갑옷·보조 손·XP·체력·포션 효과를 캡처한다. 계정마다 다른 표식 아이템을 두면 복원 누락이나 중복을 비교하기 쉽다. 경기 진입 후 장비는 시나리오에 맞게 확보한다. 통제 전투에는 같은 검·활·철 갑옷, 화살, 황금사과, 망원경, 다이아몬드를 준비한다. 자연스러운 템포 측정 경기에서는 장비 지급과 강제 교전을 생략한다.

- **기본 실시간 경기**는 30분 파밍, 5분마다 선택, 선택당 최대 현실 15초, 30:20 목숨 제한, 40:20 서든데스를 유지한다. 선택 동안 경기 시계는 멈추므로 현실 시각은 더 늦다.
- **가속 합성 경기**는 `Phase66Checks`의 단조 벽시계 입력을 진행시킨다. 기본 경기 시간을 유지하고 15초 선택을 별도로 입력한다.
- **가속 클라이언트 반복**은 별도 Paper 데이터 폴더에서만 설정을 변경한다. 예를 들어 `game.gathering-seconds=360`, `game.selection-interval-seconds=60`, `border.shrink-duration-seconds=120`, `supply.announce-seconds=40`, `supply.coordinates-seconds=20`를 사용한다. 보급 3개 구간은 각각 75–85초, 160–170초, 260–270초로 설정한다. 그 외 설정은 기본값을 사용한다. 6회 선택, 현실 15초, 20초 리스폰, 3초 보호와 보급 개봉, 20초 유예를 유지한다. 이 설정에서 축소 시작은 6:20, 서든데스는 8:20이다. 서버의 틱 속도 명령으로 시계를 가속하지 않는다.

## 단계별 조작과 기대 결과

1. 모든 계정에서 `/aw join` 후 콘솔에서 `aw admin start`를 실행한다. `/aw status`로 `PREPARING` 동안 시계 정지, 배치 후 `GATHERING`을 확인한다. 경기장 범위, 월드, 지형과 시작점 간 최소 80블록을 기록한다.
2. 통제 경기에서 파밍 중 PvP와 일반 사망을 재현한다. 목숨 보존, 20 경기초 대기, 인벤토리·XP 유지, 현재 안전 구역 랜덤 복귀를 확인한다. 보호 3초 동안 근접·발사체 양방향 피해를 시도하고 이후 정상 피해를 확인한다. 위험 지형, 경계까지 거리와 가장 가까운 적까지 거리도 기록한다.
3. 각 선택에서 GUI의 후보 3개와 XP 레벨을 기록한다. A는 수동 선택하고 B는 14초에 대기, 15초에 자동 선택을 확인한다. 다른 계정은 선택 중 이동·공격·GUI 아이템 이동과 연결 종료를 시험한다. A는 한 번 재추첨하고 다음 회차에 다시 시도한다. 30분 최종 선택의 프리즘 3개를 확인한다.
4. 같은 보급에 두 명이 같은 완료 틱을 목표로 상호작용한다. 개봉 직전 이동·피격·다른 GUI·로그아웃을 각각 시도한다. 가득 찬 인벤토리와 여유 공간이 있는 인벤토리를 기록한다. 접속 복구 후 새로 개봉해야 하며 한 보급에서 저장한 인벤토리 델타가 한 건이어야 한다. 선택 중 개봉 타이머 정지, 관리자 종료와 개봉 경합은 각각 다른 경기에서 확인한다.
5. `/aw track`을 실행하고 다이아몬드 1개 차감과 10초 동안 방향 갱신을 확인한다. 대상 무효화와 60초 쿨다운을 확인한다. 48블록 안에서 망원경을 2초간 조준하고 화면, 통지, 현실 15초 스냅샷을 확인한다. 대상을 이동시키거나 벽 뒤로 보내 조준을 끊는다. 좌표·실시간 체력이 표시되지 않는지, Shift 클릭·숫자 키·드래그로 GUI 아이템이 이동하지 않는지 확인한다.
6. 기본 30:20 이후 첫 PvP 사망은 목숨 1개를 차감하고 부활한다. 적어도 두 명을 남긴 채 40:20에 도달하고, 서든데스 사망이 바로 탈락으로 이어지는지 확인한다. 최종 우승과 별도 경기의 동시 탈락 무승부를 기록한다. 사망 직전 10초 피해와 처치자, 리스폰 자동 표시, 최종 탈락 뒤 `/aw death`, 현실 60초 만료를 확인한다.
7. 정상 승리, `aw admin stop`, 종료 시 오프라인인 참가자를 별도 재현한다. 재접속 전후로 시작 전 스냅샷을 비교한다. 동일 계정이 두 번 접속해도 아이템 복제, 대기 작업 재실행, 보더 잔류가 없어야 한다.

## 전투 조합 기록표

`dev.combat-audit.enabled: true`와 `max-events`를 격리 서버에서 설정한다. 정상 선택으로 조합을 얻고 후보가 부족하면 다음 경기에서 반복한다. 강제 소유 부여 명령은 없다. 같은 장비, 타격 출력, 방어 상태와 초기 체력 조건에서 단일 증강과 조합을 비교한다. 전투는 파밍 단계에서 반복하고, 목숨 제한과 자기장 피해는 별도 표본으로 기록한다.

| 조합 (ID) | 재현과 볼 값 | 실전 |
|---|---|---|
| 강철심장 + 중첩 공룡 (`steel_heart`, `stack_dinosaur`) | 기본 10 경기초 쿨다운 안·밖에서 타격. 획득 중첩, 최대 체력과 20중첩 경계 | NOT_RUN |
| 강철심장 + 육중한 주먹 (`heavy_fist`) | 최대 체력 20·40·100 이상에서 원본 피해를 비교. 기존 방어 전 모델 1.6·3.2·8포인트와 대조 | NOT_RUN |
| 누적의 공명 125·150·175% | 성장 계열 2·3·4종을 갖춘 뒤 원장별 4·2·4회 같은 지급. 1단위 요청 기준 독립 검사는 5·3·7 중첩 | NOT_RUN |
| 불멸의 광전사 + 불사조 / 생명의 잔향 2·3종 | `immortal_berserker`, `phoenix_heart`, 선택적으로 `russian_doll`. 치명타 순서, 부활 횟수, 독립 보호막, 바닐라 흡수, 일반 사망 확인 | NOT_RUN |
| 마법 미사일 + 무한 반복 (`magic_missile`, `infinite_repeat`) | 동일 원본의 발사와 명중 구분, 두 번 및 세 번째 발동, 100발 진화 전후. `eureka` 추가 시 무한 포격 비교 | NOT_RUN |
| 검풍 + 궁극의 히드라 (`sword_wind`, `ultimate_hydra`) | 3번째 검기, 4번째 히드라, 검기 적중 30회 진화 전후. 벽과 광역 대상 포함. 4인 이상에서 주변 대상 추가 | NOT_RUN |
| 고유 시너지 5종 | 강철의 왕은 강철심장·중첩 공룡·육중한 주먹. 무한 포격은 미사일·유레카·무한 반복. 재앙의 기관차는 탱크 엔진·재앙의 거인·폭주 기관. 지옥의 군주는 지옥의 전도체·우주의 중심·보석 건틀릿. 천 개의 검은 검풍·히드라·양손잡이. 마지막 조각 전후로 동일 동작 반복 | NOT_RUN |

전투 한 건의 기록 양식

```text

```

경기 한 건의 기록 양식

```text
match,commit,paper,java,clients,mode,host,first_pvp_s,pvp_per_5m,kills_deaths,supply_pvp,claim_delays_s,track_uses,scout_attempts,scout_successes,scout_engagements,drafts,manual,automatic,rerolls,synergies,evolutions,game_s,wall_s,survivors_by_shrink,server_tick_samples,p95_ms,max_ms,over50,total_ticks,restore,verdict,notes
```

`Match tempo`와 `Match feature totals`는 경기 ID로 조인한다. 피해나 흡수가 있었던 양방향 참가자 쌍은 10 경기초 이상 조용했던 뒤 새 교전으로 집계한다. 구간 키는 0부터 시작하며 1은 5:00–9:59다. 보급별 등장부터 획득까지의 경기 시간은 `supply_claim_ms`로 확인한다. 축소 시작과 이후 경기 시간 1분마다 탈락하지 않은 인원을 관측 시각으로 기록하며 부활 대기 및 연결 종료 상태를 포함한다. 준비 구간을 제외한 Paper 서버 틱에 대해 p95는 1ms 버킷 상한, 최댓값은 ms, 50ms 초과는 건수/표본 수를 출력한다. 경기 중 `/spark profiler`로 추가 진단했다면 별도 경기에서 수집한 값으로 표시한다. 합성 데이터는 CI 로그 또는 `playtest-results/synthetic/`에 보관한다.

## 보급 장애와 후보 평가

보급 원장은 기존 월드 블록 복구를 계속 담당한다. 지급은 동일 경기의 메모리에서 한 번만 확정한다. `scripts/test-supply-crash.py`는 일회용 Paper 프로세스에서 실제 지급 함수로 독립 인벤토리 두 개에 쓰고, 한 쪽만 파일 스냅샷을 갱신한 뒤 `SIGKILL`과 두 차례 재기동을 수행한다. 두 재기동에서 저장한 보상은 1개, 저장하지 않은 보상은 0개여야 한다. 클라이언트 접속, 실제 Minecraft 플레이어 저장 파일, 파일을 쓰는 도중의 시스템 장애는 이 프로브 범위 밖이다.

| 관찰 | 운영 정책 |
|---|---|
| 지급 전 또는 쓰기와 원복 성공 뒤 | 월드 마커에 소유권이 있고 인벤토리 공간이 있으면 현재 경기에서 다시 개봉할 수 있다. |
| 메모리 쓰기가 성공하고 playerdata 저장 이전에 종료 | 보급 마커는 복구한다. 지급을 재생하지 않으므로 보상 유실 가능성이 남는다. |
| 플레이어 저장 완료 뒤 월드 저장 이전에 종료 | 일치하는 마커만 회수한다. 보상 재지급은 하지 않는다. |
| 쓰기 결과가 불명확하거나 종료가 경합 | 현재 경기에서 지급을 다시 시도하지 않는다. 별도 트랜잭션으로 저장 완료를 확정할 공개 API가 확인되기 전까지 자동 재지급을 유보한다. |

별도 구축을 검토할 경우 지급 ID를 경기·보급 단위로 발급하고, 기존 블록 원장과 독립된 지급 원장에 의도와 관측 결과를 기록한다. 저장 전 종료와 수동 이동·소비·경기 종료 복원은 영수증 또는 현재 인벤토리 비교만으로 판별할 수 없다. 서버가 플레이어 상태와 완료 식별자를 함께 내구성 있게 저장하는 경계를 입증하기 전에는 장애 기록을 관리자 확인용으로만 사용한다.

A/B 비교는 같은 인원수에서 기본 경기부터 여러 번 수집한 뒤 실행한다. 2–4인에서 교전이 드물면 별도 18분 파밍·3분 선택·6분 축소 경기와 비교한다. 보급 개봉은 1·2·3초간 동일 장비와 배치에서 성공률·중단·교전 및 보급 지연을 비교한다. 리스폰은 적 거리·경계 거리·위험 지형을 기록해 실패 위험을 분류한다. 이 실전 자료가 확보되기 전까지 경기 규칙을 변경하지 않는다.

고정 시드 후보 비교는 네 XP 경로와 회차당 2,000 표본을 사용했다. 표본의 주 역할은 공격·생존·기동·경제로 분류하며 교환과 재추첨은 제외했다. 동일 희귀도의 대체 후보가 있을 때만 단일 역할을 분산하고 마지막 XP 증가 후보를 대체했다. 1–6회차 기본 단일 역할 수는 174·198·249·294·335·653건이었다. 후보 규칙에서 각각 0건이었고 최종 XP 증강은 248건에서 0건으로 줄었다. 이 결과는 역할 분류와 고정 시드에 대한 합성 비교이며 실제 선호도나 승률 측정은 없다. XP 희귀도와 기본 후보는 유지했다.
