# PHASE 7.5 경기 시작과 경기장 진단

접속자를 대상으로 `/aw admin start`를 실행한다. 참가 권한이 있고 살아 있는 비관전자 중 이전 경기 복구가 필요한 사람과 자동 참가를 거부한 사람을 제외한다. 먼저 `/aw join`한 사람을 우선 배치하며, 남은 자리는 UUID 순으로 채운다. 최대 인원은 16명이고 명령 응답에 자동 등록, 정원 초과, 그 외 제외 인원이 나온다.

`/aw leave`는 대기실에서 자동 참가를 거부한다. `/aw join`으로 거부를 해제할 수 있다. 탐색이나 준비에 실패해도 거부 상태는 유지되며, 실제로 시작한 경기가 끝나면 초기화된다. 준비 중 참가자가 나가면 탐색을 취소하고 스냅샷을 복원한다. 이미 요청한 청크가 정리되면 다시 시작할 수 있다.

## 1인 연습

온라인 참가 가능 인원이 1명이고 아래의 두 기능을 켜 두면 관리자 시작 명령이 격리된 전투 실험실에서 연습을 시작한다. 플레이어든 콘솔이든 시작 명령에는 관리자 권한이 필요하다. 실험용 대상·증강·시간 조작에는 기존의 추가 실험실 권한이 필요하다. 실험 월드는 운영 월드와 다른 기존 PvP 오버월드여야 하며 다른 플레이어가 머물고 있으면 시작을 거부한다.

```yaml
game:
  auto-join-online-players: true
  allow-solo-practice: true
  min-players: 2
  max-players: 16
dev:
  combat-lab:
    enabled: true
    world: aw_lab
    allow-solo: true
    arena-size: 128
    search-radius: 128
    spawn-margin: 8
    generate-missing-chunks: false
```

실험 월드를 미리 로드한 뒤 `/aw admin test check`를 실행한다. 연습은 실제 경기 시계, 증강 선택, 경험치, 보급, 자기장과 복원 절차를 사용한다. 혼자 남았다는 이유로 우승 처리하지 않는다. 관리자 중지, 자발적 탈퇴 또는 최종 탈락 시 연습을 종료한다. 결과는 연습으로 표시되며 운영 경기장 사용 기록을 쓰지 않는다.

## 운영 경기장

```yaml
arena:
  spawn:
    min-player-distance: 40
    border-margin: 24
  biome:
    ocean-policy: MAX_RATIO
    maximum-ocean-ratio: 0.05
  search:
    max-candidate-attempts: 120
    expand-within-world-border: true
    world-border-margin: 0
    generate-missing-chunks: false
```

기존 서버의 `config.yml`에서 설정한 값이 새 기본값보다 우선한다. 기존 `ZERO`, 거리 80, 여유 50 및 후보 제한 80을 새 기본값으로 바꾸려면 위 설정을 반영하고 재시작한다. `ZERO`는 그대로 사용할 수 있으며 실제 경기에서 `commit-surface-step: 1`을 적용하면 모든 표면 열을 검사한다.

`/aw admin arena check`는 현재 보더 중심·폭과 유효 중심 범위, 초기 스폰 거리와 여유, 예상 인원, 청크 생성 정책을 보여 준다. `/aw admin arena preview`는 청크를 생성하지 않고 표본 검사와 스폰 확보를 시도한다. 준비 중에는 청크 진행량, 스폰 수와 거부 원인이 설정한 간격으로 표시된다.

운영 월드보더는 수정하지 않는다. 부동소수 보더 중심과 블록 단위 경기장 경계가 맞지 않으면 폭이 같아도 배치 공간이 없을 수 있다. 탐색은 보더에 들어가는 정수 좌표와 스폰 주변 범위의 교차 영역에서 시작한다. 범위 확장을 허용하면 보더 안에서 스폰과 가장 가까운 유효 지점 및 다른 지점을 검사한다. 구조적으로 불가능한 경우 청크를 요청하기 전에 현재 폭과 필요한 최소 폭을 출력한다.

MAX_RATIO는 32블록 구역마다 정해진 지표 한 점을 뽑고 구역의 열 개수로 가중한다. 추정치가 5%의 ±2%p 이내이거나 스폰을 추가 확보해야 하면 8블록 간격으로 다시 검사한다. 표본을 지나지 않는 작은 바다 구역이나 미생성 청크까지 확인했다는 의미는 아니다. 개별 초기 배치와 리스폰에는 중앙 충돌 공간 및 주변 3×3 지형을 다시 확인한다. 인접 지면의 높이 차이는 1블록까지 허용하며, 바다·위험 블록·액체·낙하 위험은 제외한다.

청크 부족 메시지가 나오면 먼저 월드를 사전 생성한다. 플러그인에서 생성하려면 해당 운영 또는 실험 환경의 `generate-missing-chunks`를 명시적으로 활성화한다. 생성은 서버 부하를 증가시킬 수 있다.

## 검증 범위

CI는 배치 불가능한 보더와 경계 포함 조건, 실제 Paper 블록에서의 평지·한 블록 경사·용암·바다 판정, 신규 및 기존 규칙 검사를 실행한다. 검색 비교는 이전 커밋과 현재 구현을 같은 CI 호스트, Paper 빌드 257, 고정 시드의 미리 로드된 평원에서 각각 두 번 실행한다. 결과는 다른 지형이나 실서버의 성공률을 추정하는 데 사용하지 않는다.
