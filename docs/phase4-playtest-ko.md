# PHASE 4 자기장 실전 검증

## 자동 검증

Java 25에서 아래 명령을 실행합니다. Paper 기동 검사는 테스트 전용 JAR을 별도 위치에 생성하고 Paper 26.3 서버에서 가상 보더의 중심과 크기, 월드 전역 보더 불변, 실제 피해 이벤트와 돼지 체력 감소를 확인합니다. 플레이어 접속이나 화면 표시는 이 검사의 범위에 포함되지 않습니다.

```bash
./gradlew clean build paperProbeJar --stacktrace
bash scripts/test-domain.sh
AW_BORDER_PROBE=1 RUNNER_TEMP="$(mktemp -d)" bash scripts/test-paper-smoke.sh
git diff --check
```

## 실제 클라이언트 두 대

1. 테스트용 Paper 26.3 서버에 `build/libs/`의 AugmentWild JAR만 설치합니다. PvP가 허용된 기존 오버월드를 준비하고 `arena.world`에 그 이름을 지정합니다. 기본 검색 범위를 사용할 경우 미리 생성된 육지 청크가 필요합니다.
2. 두 클라이언트로 접속하고 플레이어의 위치, 모드, 인벤토리·갑옷·보조 손, XP, 체력·허기, 효과·비행 상태를 기록합니다. 두 플레이어가 `/aw join`을 실행하고 관리자가 `/aw admin start`를 실행합니다. `PREPARING` 동안 시계가 0에서 움직이지 않는지, 배치 후 좌표가 영역 안이고 80블록 이상 떨어졌는지 확인합니다.
3. 파밍 중 두 플레이어가 실제로 공격하고 한 명이 사망하도록 합니다. 네이티브 리스폰 이후 경기 시간 20초에 맞춰 안전한 새 좌표로 복귀하는지 확인합니다. 보호 3초 동안 들어오는 피해와 직접 공격·발사체 등 나가는 피해를 확인하고, 보호 종료 후 다시 전투합니다. 파밍 중 10회 반복해 목숨, 아이템·XP, 예약 중복을 확인합니다. 별도 시도에서 이동 이벤트가 취소되는 테스트 플러그인을 사용해 예약이 유지되는지도 확인합니다.
4. 증강 선택 중, 축소 시작, 축소 중간, 서든데스의 `/aw status`와 보이는 경계를 기록합니다. 원래 경기장 안이면서 현재 자기장 밖에서 피해를 확인하고, 안전 영역에 재진입해 다음 피해가 없는지 확인합니다. 축소 도중 사망시켜 리스폰 후보가 줄어든 현재 영역 안에 있는지 확인합니다. 빠른 별도 반복에서는 파밍·선택 간격과 함께 보급 시간 및 축소 시간을 일관되게 줄일 수 있습니다. 기본 30:20과 40:20 확인에는 기본 설정을 사용합니다.
5. 경기 중 재접속 후 현재 가상 경계를 확인합니다. 탈퇴와 관리자 종료를 각각 재현해 기존 보더와 참가 전 상태가 복원되는지 확인합니다. 마지막으로 테스트 서버 정상 재시작과 비정상 종료를 별도로 재현해 복구 파일 유지와 재접속 시 단일 복원을 확인합니다. 기존 전역 보더는 시작 전과 종료 후 `/worldborder get` 및 비참가 클라이언트의 화면을 비교합니다.

실행하지 않은 실플레이 항목은 `NOT_RUN`으로 남깁니다. 기동 테스트의 결과를 `REAL_CLIENT_VERIFIED`로 전환하지 않습니다.
