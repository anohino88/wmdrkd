# 파일 형식과 복구

## 경기 결과

`plugins/AugmentWild/match-history/<경기 UUID>.tsv`에 종료한 경기 한 건을 하나의 파일로 기록한다. 경기가 실제로 시작된 뒤의 중단도 유형·종료 사유를 표시해 저장한다. 준비 도중 중단된 경기는 참가 전 복구 자료만 사용한다.

헤더의 순서는 스키마 번호 1, 경기 UUID, 플러그인 버전, 규칙 지문, UTC 시작·종료, 경기 유형, 결과, 우승자 UUID 또는 `-`, 경기 시간 초다. 버전과 지문은 Base64 URL 인코딩이다. 지문은 로드된 경기 규칙과 증강·시너지·공명 설정 문서에서 계산하며 런타임 밖의 외부 플러그인 변경을 나타내지 않는다.

- `p`행에는 참가자 UUID, 순위, 처치·사망·목숨·생존 초, 확인된 가한·받은 HP, 회복 HP, 보호막 흡수, 마지막 레벨과 온라인 확인 여부, 스킬 사용·보급 획득 수, 최종 보유 ID, 진화·시너지·공명·획득 및 스킬별 성공 횟수 요약이 들어간다. 목록은 줄바꿈을 사용한 Base64 URL 인코딩이다. 순위 0은 중단, 목숨 -1은 미확인이다.
- `s`행은 보급 ID와 사건 키, 0 이상의 값이다. `_ms`는 밀리초 단위 경기 시간, 그 외는 횟수다. 접근은 설정된 상호작용 거리에서 열린 유효 접근을 초 단위로 표본 확인하거나 실제 개봉 시작으로 확인한다.
- 목록 인덱스는 최신 4,096개다. 인덱스 범위 밖의 보관 중 기록은 UUID로 조회할 수 있다. UUID를 정규 형식으로 검사하고 정해진 디렉터리에서 읽는다. 일반 조회는 본인 참가 기록만 전달하며 관리자 권한은 예약 때와 응답 때 확인한다.

## 성공과 실패의 경계

두 원장은 불변 스냅샷을 독립 단일 작업자로 전달한다. 결과 파일은 같은 디렉터리의 임시 파일에 쓰고 동기화한 다음 원자 교체한다. 파일명을 포함해 스키마·경기 ID·중복 행·크기를 검증한다. 심볼릭 링크는 읽지 않는다. 파일별 상한은 512,000바이트다. 결과 파일 손상은 `match-history/quarantine/`에 원본을 이름 변경해 보존한다. 이전 증강 TSV 손상본은 기존 방식에 따라 WARN을 내고 제자리에 보존한다.

결과는 기본 90일을 보관하며 기존 `telemetry-retention-days`를 사용한다. 보관 범위를 벗어나면 조회에 표시되지 않는다. 정상 종료는 각 작업자의 종료를 최대 400ms 기다리고, 미저장 UUID와 남은 작업 수를 기록한다. 디스크 오류가 지속되면 메모리의 최대 64개 미저장 결과를 관리자 재시도로 다시 쓸 수 있다. 프로세스가 강제로 종료되면 원자 교체 이전 미저장 내용은 유실될 수 있다. 정상적으로 커밋된 파일은 다음 시작에서 다시 조회한다. 전원 차단 내구성은 파일시스템에 의존한다.

이 원장은 보상, 인벤토리, 월드 복구의 근거로 사용하지 않는다. 복구 실패 시 원래 복원 스냅샷과 보급 소유권 기록을 점검한다. 결과 재시도는 복원·아이템 재지급을 실행하지 않는다.

## 운영 통계

기존 `analytics/<경기 UUID>.tsv`의 스키마 1을 유지한다. 버전 `8.2.1`은 기존 제시 키 외에 `pick/<증강>/<희귀도>/<회차>`와 진화 대상 수, 공명 활성 횟수를 포함한다. 운영 2인 이상 승리·무승부 경기만 들어가며, 별도로 보관한 중단·연습·실험 기록은 제외한다. `export.csv`에는 제한된 영문 ID·수치·UUID·타임스탬프만 들어가며 플레이어 이름이나 플레이어 UUID가 없다.

[자동 검사](../../../src/test/java/io/github/augmentwild/paper/MatchArchiveTest.java)에서 중복 저장, 참가자 권한 분리, 재개, 쓰기 실패와 재시도, 손상·초과 파일 격리 및 보관 기간을 확인한다. 강제 종료 중 새 결과 파일의 생성 경계는 별도 프로세스 시험 대상이다.
