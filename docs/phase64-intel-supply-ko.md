# PHASE 6.4 정보전과 보급

| 기능 | 조작 | 기본 동작 |
|---|---|---|
| 방향 추적 | `/aw locate` 또는 `/aw track` | 다이아몬드 1개로 가장 가까운 유효 생존 적을 경기 시간 10초 동안 8방향으로 표시. 재사용 60초. 좌표·거리·높이는 비공개이며 이름도 기본 비공개 |
| 망원경 정찰 | 바닐라 망원경으로 상대를 연속 2초 관찰. `/aw scout`로 다시 열기 | 최대 48블록에서 실제 사용 상태와 시야 검사. 재사용 60초, 읽기 전용 결과는 현실 15초. 대상에게 정찰 사실을 알림 |
| 사망 분석 | 기본 리스폰 후 자동 표시 또는 `/aw death` | 경기 시간 최근 10초의 체력 피해, 흡수, 처치자·기여자와 식별된 발동 효과를 표시. 결과는 기본 현실 60초 동안 확인 가능 |
| 보급 | 나타난 상자에 주손으로 우클릭하고 자리를 지키기 | 일반 각 1개가 6~10분과 14~20분, 고급 1개가 23~28분 사이에 등장. 2분 전 예고, 1분 전 좌표. 기본 경기 시간 3초 개봉 |

정찰 화면에는 보유 증강 이름·희귀도·기본 설명, 보유 수와 활성 고유 시너지·계열 공명 이름이 표시된다. 페이지 전환을 지원한다. 정확한 중첩, 체력, 부활 잔량, 쿨다운, 위치, 인벤토리와 선택 후보는 정찰 스냅샷에 포함하지 않는다. 조준 대상 변경, 장애물, 망원경을 놓거나 증강 선택에 들어가면 연속 조준을 초기화한다.

피격 기록은 참가자마다 기본 128건으로 제한한다. Bukkit 피해 이벤트 하나를 한 번 기록하고 체력 손실은 당시 잔여 체력을 상한으로 삼는다. 기존 흡수와 생명의 잔향에 흡수된 양은 체력 피해와 따로 합산한다. 원본 ID와 파생 증강 ID는 전투 엔진에서 확인 가능한 경우만 이어 붙인다. 일반 피해에 섞인 여러 증강의 피해량을 임의로 분해하지 않는다. 기록 원장은 경기 종료 시 비운다. 마지막 사망처럼 종료 후 기본 리스폰하는 경우에 대비해 완성된 본인 보고서는 유효시간까지 열 수 있다.

보급 위치는 경기장 검색에서 검증한 지표 후보 중 현재 안전 구역, 높이, 간격, 접근성, 기존 상자 간섭을 확인해 예약한다. 공개한 위치가 등장 전에 막히면 보급을 취소하고 알린다. 보상은 보급 시점에 세트 하나를 추첨하며 플레이어의 XP나 장비를 읽지 않는다. 일반 보급의 경험치 병은 다음 증강 선택을 간접 지원한다. 기존 경기당 재추첨 횟수는 같다. 상자는 빈 물리 블록으로 표시하고 보상은 경기 상태에 보관한다. 이동·피격·접속 종료는 해당 개봉을 중단한다. 인벤토리가 부족하면 아이템을 일부 지급하지 않고 다른 유효한 개봉 시도가 계속될 수 있다. 관리 종료 시 마커와 청크 티켓을 정리한다. 서버 프로세스가 강제 종료되면 당시 설치된 빈 마커가 남을 수 있으며, 재시작 후 보상을 복구하지 않는다.

추적과 쿨다운, 연속 조준 진행, 보급 시간표와 개봉은 경기 시간을 사용한다. 증강 선택 중에는 보급 진행과 추적 시간 계산이 멈춘다. 정찰 및 사망 결과 유효시간은 현실 시간이며 선택 GUI의 입력 제한도 기존 현실 시간 기준이다.

## 설정과 파일

- `config.yml`의 `tracker`, `scouting`, `death-review`, `supply`에서 조정한다. 과거의 고정 보급 시간 키 대신 `supply.windows`와 `supply.rewards`를 사용한다.
- 보급 보상은 일반·고급 각각의 목록에서 세트 하나를 고른다. 항목 형식은 `MATERIAL*수량`, `POTION:종류`, `MATERIAL:마법부여:레벨`, `BOOK:마법부여:레벨`이다.
- `PaperMatchService`는 생존 판정과 공용 시계, `PaperIntel`은 명령·정찰·개인 보고서, `PaperSupply`는 보급 시간표·월드 이벤트와 지급을 연결한다. `PaperOfficialCombat`에서 확인된 피해 출처와 보호막 양을 전달한다.

## 확인 절차와 범위

- 독립 검사에서는 비용·쿨다운의 중복 차단, 3차원 최근접 판정과 동률, 2초 연속 조준 경계와 초기화, 스냅샷 만료, 여러 공격자와 피해·흡수 합계, 보급 창과 예고 시각, 성공한 지급만 한 번 확정되는 원장을 확인했다.
- 2·8·16 가상 참가자 규모에서 각각 2,000회 순회해 최근접 검색과 기록 크기 128건을 검사했다. 로컬 누적 시간은 20.048·50.269·78.720ms였다. Paper 합성 전투 부하와 별개이며 실제 클라이언트·네트워크·서버 틱 성능은 미측정이다.
- 두 실제 클라이언트에서 상대가 없는 동안 다이아몬드가 유지되는지, 이동·탈락 시 방향이 변하거나 끊기는지, 망원경 조준 해제·벽·48블록·대상 교체가 진행을 초기화하는지 확인한다. 정찰 직후 교환하여 이전 스냅샷이 그대로인지, 다음·이전 페이지와 쉬프트 클릭으로 아이템을 꺼낼 수 없는지 확인한다.
- 두 플레이어가 보급 상자를 동시에 개봉해 한 명만 획득하는지 확인한다. 이동·피격·로그아웃·인벤토리 부족과 선택 일시정지를 각각 반복한다. 일반 사망과 최종 탈락에서 실제 기여량, 흡수, 원인과 결과 화면을 비교한다. `REAL_CLIENT_VERIFIED = NOT_RUN`이다.

Paper 프로브에서는 기존 나침반을 보존하며 다이아몬드 하나를 차감하는 인벤토리 계산, 공간 부족 시 부분 지급 차단, 빈 상자 마커 생성과 원래 블록 복원, 다른 소유 마커 보존, 시야 거리 및 장애물을 확인했다. 별도의 기존 Paper 합성 전투에서는 엔티티 2·8·16개에서 실제 피해 이벤트 60·240·480건을 확인하고 모든 테스트 엔티티를 정리했다. [실행 기록](https://github.com/anohino88/wmdrkd/actions/runs/44458233133)
