# PART A. HUD 정보 전달 시스템 전면 개선

## 3. 현재 HUD 구조 분석

우선 다음 파일을 조사한다.

- `PaperHud.java`
- `HudMessages.java`
- `PlayerUi.java`
- `CombatFeedback.java`
- `CombatView.java`
- `PaperArt.java`

현재 HUD는 여러 정보가 하나의 액션바를 공유하며 높은 우선순위 메시지가 낮은 우선순위 메시지를 가리는 구조를 사용한다.

예상되는 문제:

- 피해량 표시 중 스킬 쿨다운이 가려짐
- 증강 발동 알림으로 중요한 정보가 사라짐
- 여러 메시지가 연속해서 발생할 때 일부 정보가 표시되지 않음
- 자기장 경고와 스킬 상태가 경쟁함
- 플레이어가 현재 사용 가능한 스킬을 즉시 파악하기 어려움

실제 코드와 테스트로 재현한 뒤 수정한다.

## 4. 정보 채널 분리

HUD를 다음 정보 그룹으로 구분한다.

### 지속 정보

- 현재 스킬 3개
- 선택된 스킬
- 쿨다운
- 충전 횟수
- 경기 단계
- 다음 증강까지 남은 시간
- 현재 자기장 상태
- 남은 목숨

### 순간 정보

- 피해량
- 회복량
- 증강 발동
- 치명타
- 방어 성공
- 스킬 사용 실패
- 진화 및 시너지 활성화

### 긴급 정보

- 자기장 밖 경고
- 생존 위기
- 위험 지역
- 증강 선택 마감 임박
- 중요한 경기 상태 변경

모든 정보를 동일한 액션바에서 경쟁시키는 구조를 피한다.

Minecraft 기본 클라이언트에서 실제 지원되는 액션바, 보스바, 사이드바, 타이틀, 채팅 및 제한된 커스텀 글리프를 활용한다.

자유로운 화면 좌표 배치가 기본 클라이언트에서 지원된다고 가정하지 않는다.

## 5. 3슬롯 스킬 HUD

스킬 상태를 전투 중 지속적으로 확인할 수 있도록 한다.

각 슬롯에 다음 정보를 표시한다.

- 고유 아이콘
- 슬롯 번호
- 현재 선택 여부
- 사용 가능 여부
- 남은 쿨다운
- 충전 횟수
- 일시적인 사용 제한
- 빈 슬롯

상태별 디자인:

- READY: 선명한 아이콘과 준비 완료 표시
- SELECTED: 명확한 외곽선
- COOLDOWN: 감소하는 숫자 또는 진행 상태
- LOCKED: 잠금 표식과 실제 제한 이유
- EMPTY: 비어 있는 슬롯
- ACTIVE: 현재 지속 중인 스킬
- CANCELLED: 발동 취소 피드백

색상만으로 상태를 구별하지 않는다.

증강 발동 및 피해량 알림이 계속 발생하더라도 스킬 상태를 확인할 수 있어야 한다.

## 6. HUD 메시지 스케줄러

기존 메시지 우선순위 시스템을 개선한다.

다음 정책을 지원한다.

- 지속 정보 보존
- 순간 알림 병합
- 동일 메시지 중복 방지
- 메시지별 만료 시간
- 중요 메시지의 최소 표시 시간
- 긴급 메시지 우선 처리
- 긴급 메시지 종료 후 기존 정보 복원
- 낮은 우선순위 메시지의 무기한 기아 방지

예를 들어 짧은 시간에 동일 증강이 여러 번 발동했다면 다음처럼 통합할 수 있다.

`강철심장 발동 ×3`

다만 발동하지 않은 횟수를 표시하거나 실제 효과 수치를 변경하지 않는다.

## 7. HUD 프리셋

기존 화면 설정을 유지하면서 다음 프리셋을 제공한다.

- STANDARD: 핵심 정보와 주요 연출
- COMBAT: 전투 정보 우선
- MINIMAL: 필수 정보 중심
- DETAILED: 성장 및 통계 정보 추가

기존 LOW / STANDARD / HIGH / ULTRA 그래픽 품질 설정과 정보 표시 프리셋은 독립적으로 관리한다.

플레이어 설정은 재접속 후에도 유지한다.

### 완료 조건 A

- 반복적인 증강 발동 중에도 스킬 상태를 확인할 수 있다.
- 자기장 경고가 발생하면 적절한 위치에서 즉시 전달된다.
- 긴급 정보가 끝나면 일반 HUD가 복원된다.
- HUD의 갱신이 지나치게 빈번하지 않다.
- 리소스팩 미적용 상태에서도 기능이 유지된다.

# PART B. 스킬 조작 및 신규 플레이어 경험

## 8. 기존 입력 방식 유지 및 개선

현재 존재하는 다음 입력 방식을 조사한다.

- 웅크리기 + 핫바 1\~3
- 웅크리기 + F
- 메뉴 기반 전환
- 명령어 기반 스킬 사용

기존 조작 방식을 무조건 삭제하지 않는다.

서버 플러그인에서 실제 감지할 수 있는 Minecraft 입력 이벤트를 이용하여 조작 흐름을 개선한다.

클라이언트 모드 없이 R, Z, X, C 등 임의 키를 자유롭게 감지할 수 있다고 가정하지 않는다.

## 9. 스킬 입력 피드백

플레이어가 스킬 사용을 시도했을 때 다음 상태를 구별한다.

- 정상 발동
- 쿨다운
- 충전 부족
- 빈 슬롯
- 부활 보호
- 일시정지
- 경기 외부
- 탈락
- 대상 없음
- 유효하지 않은 위치
- 스킬별 발동 조건 불충족

실패 시 실제 판정 결과를 읽어 이유를 알려준다.

실패한 발동에 성공 효과음이나 성공 애니메이션을 사용하지 않는다.

중복 이벤트로 인해 스킬이 두 번 사용되거나 쿨다운이 잘못 소비되는 문제가 없어야 한다.

## 10. 최초 스킬 획득 안내

플레이어가 처음 액티브 스킬을 획득했을 때 다음을 안내한다.

- 획득한 스킬명
- 스킬의 핵심 효과
- 자동 등록된 슬롯
- 현재 설정된 사용 방법
- 실제 쿨다운
- 스킬 사용 조건

첫 획득 이후 같은 안내를 반복적으로 출력하지 않는다.

입력 방식 변경 후에는 변경된 조작 방법을 알려준다.

## 11. 신규 플레이어 가이드

새 플레이어가 복잡한 명령어를 외우지 않아도 게임을 이해할 수 있도록 한다.

가이드 내용:

1. 경기 참가 방법
2. 파밍과 성장
3. 증강 선택
4. 액티브 스킬 사용
5. 진화와 시너지
6. 보급 상자
7. 다이아 적 탐지
8. 자기장
9. 리스폰
10. 최종 승리 조건

실제 적용된 설정을 기준으로 설명한다.

기존 전투 실험실과 촬영 모드를 활용한 조작 연습 기능도 제공한다.

연습 완료에 따른 실제 경기 보상이나 전투 능력 강화는 추가하지 않는다.

### 완료 조건 B

신규 플레이어가 관리자에게 조작법을 직접 질문하지 않고도 기본적인 증강 선택과 스킬 사용을 할 수 있어야 한다.

기존 Minecraft의 아이템 교체, 보조손 사용, 인벤토리 등의 기본 조작과 충돌하지 않는지 검사한다.

## 12. 디자인 품질 기준

현재 AugmentWild보다 조금 더 보기 좋다는 정도를 목표로 삼지 않는다.

고품질 Minecraft RPG 서버, Blockbench 작품, 전문적인 판타지 게임 UI 등을 조사한다.

사용자가 이전에 제공한 레퍼런스에 접근할 수 있다면 이를 최우선으로 활용한다.

접근할 수 없는 레퍼런스는 확인하지 못했다고 기록한다.

기존 디자인이 부족하다면 해당 에셋을 폐기하고 새로 제작할 수 있다.

다음은 업그레이드로 인정하지 않는다.

- 기존 아이콘의 색상만 변경
- 테두리만 변경
- 슬롯 위치만 이동
- 동일한 문양을 반복적으로 사용
- 기존 GUI를 다시 렌더링
- 실제로 사용할 수 없는 오프라인 시안만 생성

## 13. 통합 디자인 시스템

기존의 고대 마법 문명, 다크 판타지, 마법 기계공학 스타일을 계승한다.

모든 화면에서 다음 디자인 요소를 통일한다.

- 색상 체계
- 글꼴 사용 원칙
- 버튼의 형태
- 희귀도 프레임
- 정보 강조 방식
- 메뉴 이동 버튼
- 활성화 상태
- 비활성화 상태
- 경고 및 성공 표시
- 아이콘의 크기와 여백

버튼과 장식이 명확히 구분되어야 한다.

## 14. 전체 GUI 개편 대상

다음 화면을 전수 조사하고 실제 사용 화면을 개선한다.

- 메인 메뉴

- 증강 도감
- 증강 상세

- 시너지 및 공명 정보
- 스킬 설정
- HUD 설정
- 그래픽 설정
- 보급 안내
- 적 탐지
- 전투 기록

- 경기 결과
- 전투 실험실

- 리소스팩 진단

기존 화면의 기능과 연결 관계를 조사한다.

화면마다 별도의 디자인을 무작위로 제작하지 않고 공통 UI 구성 요소를 재사용한다.

## 16. 증강 선택창

세 후보를 명확하게 구분하고 비교하기 쉬운 구조로 제작한다.

각 후보에 표시할 정보:

- 증강명
- 희귀도
- 고유 아이콘
- 핵심 효과
- 실제 효과 수치
- 능력 계열
- 발동 조건
- 현재 보유 증강과의 관계
- 진화 가능성
- 시너지 완성 여부

현재 보유한 증강과 조합했을 때 시너지가 완성된다면 명확하게 강조한다.

추천 표시는 참고 정보일 뿐이며 임의로 선택을 강제하지 않는다.

숨겨진 확률이나 실제로 존재하지 않는 조합을 표시하지 않는다.

카드 디자인은 고급화하되 실제 클릭 위치를 유지한다.

선택 제한시간과 재추첨 가능 횟수도 실제 값으로 표시한다.

## 17. 증강 도감 및 상세 화면

- 디자인 완성도

품질이 낮은 아이콘은 완전히 새로 제작한다.

PHASE 7.4에서 해결했던 화면 가림 오류를 재발시키지 않는다.

# PART E. 성장 단계별 모델 변화

## 24. 실제 성장 데이터 연결

현재 구현된 성장형 증강을 전수 조사한다.

각 증강의 실제 성장 조건과 값을 확인한다.

- 현재 누적량
- 최대 누적량
- 성장 단위
- 성장 제한
- 진화 조건
- 현재 진화 여부
- 경기 중 초기화 및 복원 조건

새로운 성장 수치나 추가 능력치를 임의로 도입하지 않는다.

## 25. 시각적 성장 단계

기존 성장 수치를 시각적으로 표현하는 단계를 도입한다.

최대 성장량이 존재하는 경우의 기본 표현 예시:

| 진행률     | 시각적 단계   |
| ------- | -------- |
| 0\~24%  | 기본 형태    |
| 25\~49% | 부분 성장    |
| 50\~74% | 강화된 형태   |
| 75\~99% | 완성 직전    |
| 100%    | 최대 성장 형태 |

이 단계는 시각적 구분이다.

추가 피해, 방어력, 발동 확률 등의 실제 게임 효과를 새로 지급하지 않는다.

최대 성장량이 없거나 다른 방식의 성장 조건을 가지는 증강은 실제 데이터에 적합한 별도의 표현을 사용한다.

## 26. 대표 성장 모델

기존 증강의 실제 조건을 확인한 후 다음과 같은 디자인을 적용한다.

### 강철 계열

작은 금속 코어 → 외곽 장갑판 → 완성된 강철 구조.

### 검술 계열

단일 검기 → 보조 칼날 → 정렬된 다중 검 구조.

### 기계 계열

기본 동력 장치 → 추가 회전부 → 완성된 기계 구조.

### 마법 계열

작은 룬 → 다층 룬 → 완성된 마법 문양.

### 생명 계열

작은 생명 에너지 → 확장되는 구조 → 완성된 보호 및 회복 문양.

예시는 실제 성장형 증강에 적합한 경우에만 적용한다.

## 27. 성장 HUD 및 도감

성장 진행 상황을 플레이어가 쉽게 확인하도록 한다.

- 현재 성장량
- 목표 성장량
- 진행률
- 다음 시각적 단계
- 진화 조건
- 현재 적용 중인 실제 효과

성장 단계가 변경되면 짧은 전용 피드백을 제공한다.

매번 작은 수치가 증가할 때마다 대형 이펙트를 실행하지 않는다.

## 28. 진화 연출

실제 진화가 완료되는 순간 다음을 표현한다.

- 이전 모델의 형태
- 에너지 집중
- 기존 부품의 분리
- 새로운 구조의 결합
- 완성된 진화 모델
- 전용 효과음
- 충분한 유지 구간

진화 획득 연출과 반복 전투 연출을 구별한다.

영구적으로 Display를 생성해 둘 필요가 없는 성장 표현은 이벤트 기반으로 처리한다.

### 완료 조건 E

같은 성장형 증강이라도 초기 상태와 최대 성장 상태를 시각적으로 구별할 수 있어야 한다.

성장 판정과 실제 효과에는 변경이 없어야 한다.

# PART F. 보급 시스템 개선

## 29. 기존 보급 규칙 보존

`PaperSupply.java`와 관련 도메인 모델, 설정, 복원 로직을 조사한다.

일반 보급 2회, 고급 보급 1회 및 기존 등장 시간 범위와 아이템 내용물 확률을 유지한다.

사용자 승인 없이 보급 보상을 상향하거나 하향하지 않는다.

## 30. 보급 발견 및 접근 경험

보급 등장 과정의 시각적 완성도를 개선한다.

- 보급 등장 안내
- 일반·고급의 고유 외형
- 식별 가능한 기둥 또는 문양
- 기존 공개 정책에 맞는 방향 안내
- 거리 정보
- 현재 보급 상태
- 획득 완료 표시

보급 위치를 공개하는 범위는 기존 게임 규칙을 준수한다.

원래 공개되지 않던 위치 정보를 모든 플레이어에게 추가로 노출하지 않는다.

## 31. 보급 상자 모델

일반 보급과 고급 보급의 외형을 구별한다.

일반 보급:

- 견고한 금속 상자
- 은색 또는 청색 장식
- 명확한 개봉 상태

고급 보급:

- 정교한 금색 및 수정 구조
- 독립적으로 움직이는 잠금 장치
- 고유한 에너지 문양
- 특별한 등장 및 개봉 효과음

## 36. 통계 계산 기준

다음 수치를 구별한다.

- 선택률 = 선택 횟수 / 제시 횟수
- 보유율 = 해당 증강 보유 참가 기록 / 전체 유효 참가 기록
- 보유 시 승률 = 해당 증강을 보유한 승리 참가 기록 / 해당 증강 보유 참가 기록
- 진화율 = 진화 성공 기록 / 해당 진화의 유효 대상 기록
- 스킬 성공률 = 실제 성공 횟수 / 유효한 사용 시도 횟수

분모가 0이거나 표본이 부족하면 계산 불가 또는 표본 부족으로 표시한다.

다음 요소를 분석에 반영한다.

- 선택 회차

- 참가 인원
- 경기 길이

- 다른 증강과의 조합
- 진화 여부

**HUD:** 핵심 정보가 다른 알림에 의해 불필요하게 가려지지 않는다.

# 59. 최종 개발 지시

이번 PHASE 8.2는 AugmentWild의 전체적인 플레이 경험을 개선하는 대규모 개발 단계다.

단순히 기능 목록을 채우거나 기존 GUI를 조금 수정하는 방식으로 작업하지 않는다.

사용자가 실제로 게임을 플레이하면서 다음과 같은 차이를 체감할 수 있어야 한다.

- 전투 중 중요한 정보를 놓치지 않는다.
- 스킬을 사용하는 방법이 직관적이다.
- 증강 선택과 조합의 관계를 이해할 수 있다.
- 게임 화면이 통일된 고품질 디자인을 갖는다.
- 능력마다 다른 형태와 움직임이 나타난다.
- 성장하는 과정이 눈에 보인다.
- 보급의 등장과 획득이 명확하다.
- 사망 원인과 경기 결과를 이해할 수 있다.
- 관리자가 반복적인 설정 오류를 쉽게 진단할 수 있다.

기존 게임 규칙을 임의로 변경해서 이러한 목표를 달성하지 않는다.

특히 PHASE 8.1에서 개선한 애니메이션 가시 시간을 다시 줄이지 않는다.

작업은 내부 마일스톤별로 진행하며 각 단계의 실제 코드, 결과물 및 검증 기록을 남긴다.

전체 명세를 저장소에 기록하고 요구사항 누락 여부를 마지막까지 확인한다.

계획서만 작성하고 작업을 종료하지 않는다.

실제 코드 수정, 모델 제작, 테스트, 빌드, `origin/work` 반영 및 GitHub Actions 검증까지 수행한다.

**최종 목표: 화려하기만 한 미니게임이 아니라, 처음 접하는 플레이어도 이해할 수 있고 반복해서 플레이할 가치가 있는 완성도 높은 AugmentWild를 만드는 것.**

## **이번 업데이트 이후의 목표**

**전투 직관성**

스킬 상태, 피해, 위험 요소를 즉시 파악

**시각적 완성도**

통일된 GUI와 능력별 고유 디자인

**성장 체감**

수치뿐 아니라 모델과 움직임도 성장

**전략적 깊이**

증강 조합, 성장 조건, 실제 경기 데이터 활용

**운영 안정성**

통합 진단과 안전한 설정 갱신

이번 프롬프트는 상당히 큰 작업이므로 8.2A\~8.2F로 분할했어. 단계명, 사망 분석의 기본 조회 시간 15초, 성장 시각화의 25% 단위 등은 내가 제안한 설계값이며, 기존 게임 규칙을 변경하는 수치는 아니야.
