# PHASE 6.5 운영 안정화

## 보급 복구

플러그인 데이터 폴더의 `supply-recovery/<token>.yml`에는 경기 UUID, 월드 UUID와 이름, 블록 좌표, 원래 블록 데이터, 무작위 마커 토큰, `PLANNED` / `PLACED` / `RESTORING` 상태를 저장한다. 파일 쓰기는 임시 파일 동기화와 원자적 교체를 사용한다. `PLANNED` 저장이 끝난 후에만 상자를 설치한다. 원장은 물리 마커용이며 보상과 개봉 진행은 현재 경기 메모리에만 있다.

기동할 때와 새 경기 직전에 기록을 스캔한다. 대상 월드는 UUID로 확인하고 기존 청크를 생성 없이 로드한다. 토큰이 일치하고 비어 있는 단일 보급 상자만 원래 블록 데이터로 복원한다. 이미 공기인 위치는 복원할 물리 마커가 없으므로 현재 블록을 보존한다. 청크 저장이 끝난 뒤 해당 원장을 삭제한다. 월드나 기존 청크가 없거나, 블록 소유권이 다르거나, 상자에 아이템이 있거나, 저장이 실패하면 원장과 블록을 남기고 새 경기 시작을 막는다. 서버 로그와 원장의 월드·좌표·토큰을 함께 확인하면 충돌을 찾을 수 있다. 업그레이드 전부터 남아 있던 원장 없는 상자와 생성 중 남은 무표식 상자는 운영자가 소유권을 확인해야 한다.

정상 경기 종료에는 해당 마커를 지우고 세계별로 저장해 원장을 정리한다. Paper가 플러그인 비활성화 중 세계 저장을 거부하면 원장을 다음 기동까지 보존한다. 기존 월드를 생성하거나 복제하지 않는다. 보급 세트와 개봉 세션은 재기동 시 폐기된다. 보상 인벤토리 저장 전에 중단될 경우 보상이 유실될 수 있고, 재기동한 세션에서 다시 지급하지 않는다. 월드 마커 복구는 플레이어 저장과 묶인 디스크 트랜잭션을 제공하지 않는다.

## 경쟁 개봉과 위치

동일 틱 완료는 경기 시간의 완료 시점과 UUID 순으로 처리한다. 살아 있고 접근 가능하며 움직이지 않은 사람만 지급을 시도한다. 피해, 이동, 외부 이동, 로그아웃, 다른 GUI의 성공적인 열기는 개봉을 중단한다. 증강 선택 구간에는 시간과 개봉을 멈추고 선택 화면을 열어도 대기를 지우지 않는다. 공간 부족에는 부분 지급이 없다. 쓰기 오류 후 원복이 성공하면 재개봉할 수 있다. 원복까지 실패한 불확실한 지급은 재지급을 막고 운영자에게 기록한다.

예고 단계와 좌표 공개 직전에는 예약 위치를 재검사한다. 공개 후에는 원래 위치를 생성 직전에 다시 검사하며 실패 시 사유를 공지한다. 월드와 이미 로드된 지형, 경계, 접근 가능한 지표와 상자 주변 공간, 다른 보급과의 간격을 확인한다. 설치된 보급 마커는 경기 초마다 검사한다. 외부에서 상자를 교체하거나 내용물이 달라지면 남아 있는 획득 시도를 중단하고 해당 블록은 복구 원장 정책을 따른다.

## 정보 표시와 통계

추적 액션바는 8방향과 남은 경기 시간만 기본 표시한다. 정찰은 조준 진행률을 표시하며 대상을 바꾸거나 놓으면 진행률이 사라진다. 결과에는 분석 경기 시각과 스냅샷임을 표시한다. 추적보다 정찰 진행률을 우선하며 증강 선택, 보급 개봉 및 생명의 잔향 표시가 활성일 때 정보전 표시를 억제한다. 기존 48블록, 2초, 60초, 결과 현실 15초를 유지했다.

사망 분석은 확인된 이벤트의 체력 피해, 바닐라 흡수 및 생명의 잔향을 별도로 합산한다. 하나의 이벤트를 한 번 기록하고 같은 연쇄에 딸린 실제 별도 타격은 각각 집계한다. 증강별 피해의 분해가 불명확하면 원래 damage cause로 집계한다. 킬러는 서버가 부여한 처치자를 사용한다. 경기 종료 후에도 완성된 본인 보고서는 현실 60초 동안 조회할 수 있다.

경기 종료 때 `Match feature totals`에 보급·정보전 총계를 남긴다. 참가자 ID와 이름을 포함하지 않는다. `CLAIM_DELAY_MS`는 경기 시간의 등장~획득 지연 합이며 `OPEN_SUCCESSES`로 나누어 평균을 계산할 수 있다. 성공한 정찰 후 기본 30초 안에 정찰자와 대상 사이에서 실제 피해 또는 흡수가 발생한 첫 사건을 교전으로 집계한다. 보급 주변 PvP는 피해 대상이 열린 보급 위치 기본 12블록 안에 있을 때 피해 이벤트당 한 번 기록한다. 정찰 성공률은 `SCOUT_SUCCESSES / SCOUT_ATTEMPTS`로 계산한다. 종료 이후 사망 보고서 조회는 같은 경기 UUID에 연결해 별도 합계를 남긴다. 상세 참가자 로그의 기본값은 비활성화 상태다.

## 검증 범위

- `scripts/test-supply-crash.py`는 CI 일회용 월드와 Paper 프로세스를 별도로 만든다. 복구 준비를 마친 서버에 실제 `SIGKILL`을 보내고 같은 월드에서 두 번 기동한다. 생성 전 원장, 생성 상태가 저장된 상자, 생성 상태 전이 전의 토큰이 있는 상자, 최근 생성 마커, 지급 후 마커 제거 경계에 해당하는 상태를 검증한다. 다른 토큰의 상자와 내용물이 든 상자는 그대로 두며 두 건의 원장을 보존한다. 실제 플레이어 인벤토리 지급이나 3초 개봉 프로세스를 중단하는 검증은 별개다.
- Paper의 거래 프로브는 기존 인벤토리·상자 보호를 검증한다. 부분 쓰기 후 원복 성공 및 원복 실패는 주입된 예외로 검증한다. 동일 틱 예약 경쟁, 원복 후 재시도, 결과 불확실 시 재실행 차단은 도메인 검사 범위다.
- 통계 합성 검사에서 정찰 2시도·2성공과 유효 교전 1건을 합산하고 재교전·만료·다른 상대를 제외했다. 실제 이용률, 2·8·16인 개봉 경쟁, 정찰 GUI와 사망 UI는 `REAL_CLIENT_VERIFIED = NOT_RUN`이다.
